# ADR 0020: Focused review, page tiles and a shared image viewer

Date: 2026-10-24. Status: accepted and implemented. Verification is recorded separately in [test status](../testing/STATUS.md). Supersedes the post-capture layout in ADR 0015 and the viewer interaction in ADR 0019. Camera detection and image-processing algorithms are unchanged.

## Context

Post-capture tools compete with the image on a phone. A full-page preview in the page manager duplicates the editing workspace. Long receipts become unreadable thumbnail strips. Saving a final page before visiting another overview introduces an unnecessary step.

## Decision

- Review has Previous, Next and Finish actions. Next is primary when a following page is available; otherwise it is disabled and Finish is primary. Finish accepts the current confirmed draft and exports directly. Unreviewed imported files must be processed and reviewed or explicitly discarded before finishing.
- Review and required corner confirmation offer a visible replacement action without accepting/appending the candidate. Camera captures use Retake and the existing camera; imported images use Replace image and a direct single-image picker without camera access (D-047, unreleased source). Cancellation/failure preserves the preceding candidate and import queue; accepted pages are replaced atomically. Returning restores focus to the action. Review places replacement, direct discard and Add page beneath the document, equally distributed on mobile, with Add page on the right. Discarding a candidate or its edits preserves any already accepted page; actual page deletion remains in the manager.
- Unreleased optional `ScannerOptions.captureWorkflow: 'continuous'` keeps the camera running for a batch before review; default `review-each` preserves the preceding SDK flow (D-053). Extracted-page feedback points towards the forward Review pages count on the right, with a reduced-motion alternative and import on the left. Review opens the first unreviewed candidate or first accepted page. Retake always replaces the current page once and returns to its review. All queued captures/imports require review or explicit discard; budgets and core acceptance/export remain authoritative. Both reference hosts opt in and expose the choice.
- A grid icon opens a bounded, independently scrollable page manager. Tiles are at least 120 by 156 CSS pixels; their top-left cover crop is only a preview. Exported pages keep their complete confirmed geometry. Page actions support editing, atomic replacement, removal and movement in both directions.
- Filter, adjustment, format and quality views hide unrelated review navigation and tools. The read-only quality view has one OK button returning focus to the information trigger. In unreleased source, remove the main Undo/Original utility row and the separate Original view (D-056). Keep the complete source in the corner editor and the unoptimized current crop in held Before. Center zoom in the existing shared viewer strip, including standalone/result views, with Before on the left when provided. In page review, keep the counted information icon on the right and disable it at 0. Editing tools use Apply to retain the current recipe and Cancel to restore the previous edit settings from the original. Hide the session-close X within tools/corner editing; Escape follows local cancellation, and returning restores the trigger focus. Undo stays visibly labelled in the existing Cancel/Undo/Apply footer and stores at most twelve recipes and geometry settings from that opening, without retaining extra preview blobs or reaching earlier applied tools. Reopening starts a new local history. Individual reset icons beside the slider change only the selected tone to 0 or Lens to Auto without a manual strength; disable them at that neutral state. Filter has no extra optimization-reset action, retaining the existing Auto default and explicit profile choices.
- Export `ImageViewer` from the React entry point. Review and the reference result dialog use it. Fit uses decoded image dimensions and measured available space. Tap or double tap toggles fit/100 percent once, magnifiers step through useful scales, pinch zoom anchors at the gesture midpoint, and enlarged images can be panned. A drag must not trigger a zoom toggle. Filter and tone changes retain zoom; page changes and rotations reset it.
- Unreleased optional `ImageViewer.onPageSwipe` reports previous/next only for a horizontal one-pointer gesture at fit, without held Before. SDK review connects it for both camera workflows and imports; standalone viewers opt in. The host owns page state. SDK review adds finger-following current/ready-neighbor slides with each image's own Fit, bounded rebound and reduced-motion fallback (D-055). Raw neighbors use normal processing after releasing the outgoing view; their actual preview enters when ready. Validation/save failure keeps the current page; confirmed moves retain the existing acceptance/error/crop contracts. Zoom/pan/pinch/editing and generated-click suppression remain intact; navigation buttons remain available.
- A split-image button shows the unoptimized crop only while held. It keeps the current geometry and zoom. Pointer release outside the button, cancellation, lost capture, keyboard release, blur and visibility changes clear the comparison.
- The corner editor offers explicit Find edges in unreleased source (D-048): rerun original-based still detection, retain page settings and propose corners until Apply; Cancel, failed detection and newer manual input preserve the appropriate selection. It uses a detached loupe drawn from original pixels. Top-left and bottom-right handles show it bottom-left; the other handles show it top-left. Keyboard editing remains available. Left-handed mapping and parallel edge handles remain deferred.
- Lens Auto displays its actual result within the selected button. Portrait and landscape share the same sheet icon, rotated 90 degrees. The postcard label is split as "Post-" / "karte", with 10 by 15 cm in its accessible name and tooltip. Rotation needs no toast.
- Reference results remain available when returning to the start screen. Discarding them is explicit. PDF.js loads only when PDF is selected, renders the requested page first, keeps at most three canvases and supports retry after a preview error.

## Consequences

The viewer adds a reusable React API without moving session or processing logic into the host. Touch, keyboard, cancellation, queued errors, both themes, long receipts and the actual exported artifacts need browser regression tests. Emulated mobile views do not replace physical iPhone/Android and assistive-technology acceptance.
